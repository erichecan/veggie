01

B2B 移动端订货系统（客户前端 App / Web）

  • 未完成

    常购清单：一键快捷复购

    全库没有复购/常购清单相关代码，下单流程只是“浏览 → 加购物车 → 提交”。

  • 部分完成

    账期与专属批发价展示

    专属批发价已经实现（定价引擎 + 客户端商品接口）；账期字段存在于数据库，但客户端页面没有展示出来。

  • 已完成

    订单提交自动校验，生成标准电子销售订单

    客户下单接口校验通过后直接落成真实订单记录。

提示：目前没有独立的移动端 App，客户下单走的是同一套系统里的响应式网页，不是原生 App 或 PWA。

02

Quotation 和销售单

  • 部分完成

    创建/修改 quotation：重复商品及缺货商品提醒

    重复商品提醒已经做了；缺货商品提醒还没做，页面只显示库存数字，没有预警或阻断操作。

  • 已完成

    定价与 commission 自动计算（多层级、价格嵌套）

    价格表链式解析引擎与提成计算模块均已完整实现，接入订单流程。

  • 部分完成

    快捷按键：tab / enter 键操作

    Enter 跳转搜索框已实现；Tab 键跳行逻辑此前有 bug，最近一次修复是直接回退成浏览器默认行为，而不是自定义的 Tab 导航。

  • 已完成

    quotation / 销售单状态切换、批量操作、退回 quotation

    两者共用同一张订单表按状态区分；批量确认打印、以及“撤销确认退回 quotation”都已实现。

03

配送与司机电子签收（TMS & POD 配送端）

  • 已完成

    司机管理（批次 / 时段 / 独立配置）

    司机排班模型与管理页面完整，支持后台独立搜索。

  • 已完成

    销售单列表页快速派单

    订单列表内嵌批次选择，可就地保存派单。

  • 部分完成

    拖拽调度（按送货窗口与路线半自动派单）

    目前是纯手动的拖拽排班；系统里有计算距离/耗时的 Google Distance Matrix API 代码，但没有接进调度界面，谈不上“半自动”。

  • 未完成

    司机端 App 按序导航 + 客户电子签名（Sign on Glass）

    全库没有触屏签名捕获的代码；现在司机端的“签收凭证”其实是拍照上传，不是手写签名；也没有按顺序导航功能，只有状态按钮流程。

  • 未完成

    车辆调度：Google 地图显示司机路线图

    目前只用到了地理编码和距离计算两个 API，没有接入 Directions API，也没有任何地图可视化组件，司机端用不到地图。

  • 部分完成

    现场退改：生成电子退款凭证

    司机可以现场即时报告少货/坏货；但退款凭证要走人工审批加财务手动出具，不是“现场自动生成”。

  • 部分完成

    对账回传：签收后收款/欠款数据即时回传

    行程完成后会自动回写发票草稿、订单状态、司机提成冻结；但司机现场收的现金不会自动记成收款，现金核对目前仍靠人工比对纸质单。

07

采购管理中心

  • 部分完成

    采购计划与预测

    生鲜品类是简单的缺口补货规则，干货品类有同比外推，但都没有考虑季节性因素和促销活动，达不到“智能生成”的程度。

  • 部分完成

    询价单

    PDF 识别报价、历史报价查询已经做了；但没有向供应商在线发起询价的流程，也没有“复制历史采购单”功能。

  • 部分完成

    采购订单全流程

    创建/审核/跟踪/入库/发票的状态机很完整；但缺少独立的采购退货流程。

  • 未完成

    采购质检与验收

    到货重量核对、新鲜度分级、农残检测记录——全库都没有找到相关代码。

  • 部分完成

  • 未完成

  • 未完成

    财务报表 — 资产负债表

  • 未完成

    财务报表 — 费用分析表

提示：复式记账的底层基础设施（会计科目、分录）是存在的，只是还没有把这些底层数据组织成利润表/资产负债表这类成品报表。

09

数据分析与 BI 决策中心

  • 已完成

    经营看板

    核心 KPI 大屏 + 每日快照表已完整实现。

  • 部分完成

    客户分析（RFM）

    现有客户分层和流失预警；但没有 RFM 模型，也没有复购率这个指标。

  • 部分完成

    商品分析（ABC 分类）

    只有毛利排行做完整了；商品的 ABC 分类、系统性的畅销/滞销排行、价格敏感度分析都还没有。

  • 未完成

    销售预测（机器学习模型）

    全库检索预测/回归/时间序列/机器学习相关关键词均无命中；现有的“预测”其实是一条确定性规则公式（近期均量 + 在途订单 − 库存），没有模型、没有回测。

  • 部分完成

    灵活数据分析（Odoo 式多维度组合）

    现有 7 个分析页面本质是“预设报表 + 单维度切换”，例如毛利分析虽可选四种分组维度，但一次只能选一个，做不到“客户×月份”这种交叉组合，筛选也只有日期范围。

10

基础信息与系统管理

  • 未完成

    组织架构（多公司 / 多部门 / 多门店）

    数据模型里没有公司/部门/门店这些概念，现在是单公司单仓库架构。

  • 部分完成

    精细化角色权限

    销售侧的行级数据隔离已经做了（销售员只见自己客户）；但采购员侧的供应商数据隔离还没做，“配送中心”“打印中心”目前也只是按大类角色放行，还没做到“只有指定人员能用”的细粒度。

  • 部分完成

    商品信息管理

    分类、多规格、多单位、批次、保质期、图片、条码都齐全；只缺产地溯源这个字段。

  • 部分完成

    客户信息管理

    信用额度、账期、历史价格协议都有；但不支持一个客户挂多个地址，也没有合同文档管理功能。

  • 部分完成

    供应商信息管理

    价格、交期、起订量有记录；但没有资质证件电子版、没有供应商评级、也没有合同管理。

  • 部分完成

    系统日志与数据安全

    操作日志和登录日志很完整；但系统本身没有内置的备份恢复功能，现有备份都是数据迁移时的一次性手工快照。

11

系统部署（含双系统独立并行运行）

  • 未完成

    私有化部署能力

    当前 100% 是 GCP Cloud Run + Neon 云端 SaaS 单实例架构；数据库驱动是 Neon 专有的 serverless 适配器，没法直接接客户自己机房的普通 PostgreSQL，也没有任何“部署到客户服务器”的交付包。

  • 未完成

    与 Odoo 12 同机独立并行运行

    目前完全没有为“两套系统同机隔离部署”设计过——没有对应的容器/账号/端口隔离方案，也没有反向代理分流的规划。

  • 未完成

    管理员账号与技术资料交接机制

    目前的部署方式是开发方自己掌握所有账号（GCP 项目、Secret Manager 等），还没有一套“交给客户自主掌握”的交接流程。

  • 未完成

    自动备份（数据库 + 文件、异地存储、可恢复验证、客户可取得完整备份）

    系统层面完全空白，现有备份只是数据迁移时的一次性手工快照，没有定时任务，没有异地存储，也没做过恢复演练。

12

接口与安全

  • 未完成

    标准 API 接口对接第三方（ERP / 财务 / 电子秤 / 税控盘 / 物流）

    现有 151 个 API 路由全部是给自己前端用的，统一走 JWT session 鉴权，没有面向第三方的 API Key/OAuth 机制，没有版本号；全库搜索这几个对接对象相关关键词均为零命中。

  • 部分完成

    安全性与合规

    数据传输走 HTTPS，批次追溯链路已经实现；但没有看到专门针对《食品安全法》做的合规设计。

  • 待触发

    PDA 扫码功能

    条码字段已经有了；按合同这是“仓库商品全部有条码后可免费升级”的条件触发项，不算本阶段功能缺口。

  • 待触发

    电子秤功能

    合同写的是“生鲜出库流程改为过秤后可免费升级”，同样是条件触发项，不是 Phase 1 现在就要交付的内容。
