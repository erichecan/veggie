第二节：核心闭环流程（P0 / P1）

测试前请先走通这 4 条流程，确保系统主干路径无误

P0 流程是业务必须走通的主干路径，任何 P0 断裂即视为严重故障。P1 流程是重要但可容忍短暂中断的辅助流程。

P0

完整订单生命周期

1
运营
进入「下单」，选择客户，添加商品，选择价格模式（多价目表 / 上次价 / 默认价），确认报价单
✓ 报价单状态变为 CONFIRMED，总价计算正确
2
运营
进入「订单列表」，找到该订单，点击「生成波次」，系统创建新波次
✓ 订单状态变为 WAVE_ASSIGNED，波次编号可见
3
运营
进入「波次管理」，将波次拖拽到司机时间槽（AM/PM + 批次 + 司机名），完成分配
✓ 波次状态流转至 PICKING → PICKED → SORTING → SORTED
4
运营
进入「行程」，使用 3 步向导创建行程（选批次 → 勾选订单 → 确认），分配给司机
✓ 行程状态变为 PENDING_ASSIGNMENT
5
司机
进入「我的行程」，查看待配送行程，开始配送并核验货物
✓ 行程状态变为 IN_PROGRESS
6
司机
完成配送，上传 POD 照片（送货证明），行程标记完成
✓ 订单状态变为 IN_DELIVERY → COMPLETED
7
运营
进入「发票」，生成客户发票（选客户 → 选订单 → 确认），完成结算
✓ 订单状态变为 LOCKED，发票可打印
P0

司机结算与对账闭环

1
司机
进入「结算中心」，查看当前行程的应收账款，填入实际现金收款金额和线上收款金额
✓ 系统实时计算差额（实收 - 应收）
2
司机
确认无误后提交结算申请，状态从 PENDING 变为 SUBMITTED
✓ 提交后司机端不能再修改
3
会计
进入「对账管理」，扫描条形码或按批次筛选，找到该司机的结算记录
✓ 可看到司机汇总：现金 + 线上 + 差额
4
会计
核对金额，批量标记已退货商品，确认对账，状态变为 CONFIRMED
✓ 司机结算闭环完成，数据进入报表
P1

采购入库与库存更新

1
运营
进入「采购」，导入采购单（支持 PDF / Excel / CSV），系统自动模糊匹配商品

3
运营
进入「商品管理」，查看负库存或低库存商品（系统标红 / 橙色预警）
✓ 库存预警正确反映采购前后变化
4
老板
进入「采购分析」，查看本次采购的供应商 / 商品 / 状态维度数据
✓ 采购金额、数量在分析页面正确反映
P1

客户对账单生成与发送

1
运营
确认本周期所有客户订单已完成（状态 COMPLETED / LOCKED），并生成发票
✓ 发票列表中可见对应客户的发票记录
2
会计
进入「对账单」，点击「生成对账单」，选择客户和账期，确认生成

会计
