## 1. 计算规则（落到代码）

```
一单司机提成 driverCommissionTotal =
    Σ ( line.commissionPrice × line.deliveredQty )              // 商品件提成（快照 × 实送量）
  + order.commissionFixed                                        // 客户固定辛苦费（快照）
  + [ Σ ( line.deliveredQty × line.unitPrice ) ] × order.commissionRate   // 客户抽成（送达税前额 × 快照率）
```

- 所有输入都用**订单/订单行上的快照**（`OrderLine.commissionPrice`、`Order.commissionFixed`、`Order.commissionRate`），不实时回查主数据。
- `unitPrice` 为**税前**（项目 SSOT：unitPrice 一直税前），故抽成基数天然是税前额。
- **整单实送量为 0**（所有 `deliveredQty=0`）→ 提成 = **0**（含固定费也不计，"没去成没有辛苦费"）。
- 空值：`commissionPrice`/`commissionFixed`/`commissionRate` 为 null 时按 0 计。

## 2. 实现阶段

### Stage 1 — Schema 加字段 + 迁移
**改 `prisma/schema.prisma`：**
- `OrderLine` 加：`commissionPrice Decimal? @db.Decimal(12, 2)` （商品件提成·下单快照）
- `Order` 加三个：
  - `commissionFixed Decimal? @db.Decimal(10, 2)` （客户固定辛苦费·下单快照）
  - `driverCommissionTotal Decimal? @db.Decimal(12, 2)` （每单最终司机提成，送达冻结）
  - `commissionFrozenAt DateTime?` （提成冻结时间）

**迁移**（遵循 `prisma-migration-shadow-db` 记忆，避免 shadow DB 重放旧迁移失败）：
`npx prisma db push`（或手写迁移 SQL + `npx prisma migrate resolve --applied <name>`），再 `npx prisma generate`。
**成功标准**：generate 后新字段进入类型，TS 可用。

### Stage 2 — 新建集中计算函数（DRY）
**新建 `lib/commission.ts`**：`computeDriverCommission(order, lines)` 纯函数，返回 `{ itemTotal, customerFixed, customerPct, total }`。
- `deliveredExTax = Σ(deliveredQty × unitPrice)`；`anyDelivered = 任一 deliveredQty>0`
- `itemTotal = Σ(commissionPrice × deliveredQty)`
- `customerFixed = anyDelivered ? commissionFixed : 0`
- `customerPct = deliveredExTax × commissionRate`
- `total = anyDelivered ? round2(itemTotal + customerFixed + customerPct) : 0`
- 用 `toNum`/`round2`（`@/lib/decimal-helpers`）处理 Decimal 与 null。
**成功标准**：对齐 PRD 公式与边界（整单未送达=0）；加最小单测。

### Stage 3 — 下单写快照
**改 `app/api/orders/route.ts`：**
1. `custDefaults` 的 `select` 加 `commissionFixed: true`（~241）。
2. `tx.order.create` 的 data 在 `commissionRate` 旁加 `commissionFixed: custDefaults?.commissionFixed ?? null`（~315）。
3. 从已查的 `productsForStock` 建 `commissionMap`（productId → `Product.commissionPrice ?? template.commissionPrice`），确保该查询取到 commissionPrice。
4. `lines.create` map 加 `commissionPrice: commissionMap.get(l.productId) ?? null`（~324-337）。
**成功标准**：新建订单后 `OrderLine.commissionPrice` + `Order.commissionFixed` + `Order.commissionRate` 三快照落库。
> 加行接口 `app/api/orders/[id]/lines/route.ts` 若也建 OrderLine，同样补快照（执行时可靠法复核）。

### Stage 4 — 送达时冻结提成
**改 `app/api/trips/[id]/verify/route.ts` POST 事务（~33-50）：**
- 每个 delivery 写完 `deliveredQty` 后，同事务内：读该 order 的 `commissionFixed`/`commissionRate` + 各 line 的 `commissionPrice`/`deliveredQty`（最新）/`unitPrice` → `computeDriverCommission` → `tx.order.update`：`status:'COMPLETED'` 同时写 `driverCommissionTotal`、`commissionFrozenAt: new Date()`。
**成功标准**：核对送达后 `driverCommissionTotal` = 按实送量公式值；改主数据不影响该值。

### Stage 5 — 退货后重算
**改 `app/api/trips/[id]/returns/route.ts` PUT（approve 减 `deliveredQty` 之后，同事务）：**
- 对受影响 order 重新 `computeDriverCommission` 覆盖 `driverCommissionTotal`，`commissionFrozenAt` 更新为重算时间。
**成功标准**：退货审核减量后该单提成相应减少。

### Stage 6 — Trip.driverCommission 口径对齐
- 定位 `Trip.driverCommission` 写入点（旧口径="每家客户 commissionRate × subtotal 累加"，写入点用可靠法定位）。
- 改为：该 Trip 关联订单的 `driverCommissionTotal` 之和。
**成功标准**：`Trip.driverCommission` = 名下各单冻结提成之和。

### Stage 7 — 三个下游前端改读同一冻结数
> 执行前先用可靠法（禁沙盒 `cat -n`）读各页现状再改。
1. **财务佣金 `app/[locale]/classic/finance/page.tsx`**（~110-122）：司机佣金卡由 `completedTotal × commissionRate`（旧、不完整）改为汇总 `Order.driverCommissionTotal`（已 COMPLETED 且已冻结）。
2. **司机结算 `app/[locale]/classic/driver/settlement/page.tsx`**：显示每单提成与合计工钱，读 `driverCommissionTotal`，可分项展示。
