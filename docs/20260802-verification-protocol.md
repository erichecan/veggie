# 验证协议 — API/路由 与 UI/异常

> 2026-08-02 用户提出的两条硬要求，固化成协议。以后每个功能交付前都按此执行。
>
> 起因：此前的"验证"是纯函数单测 + curl 打接口，**UI 交互一次都没真点过**。
> 用户直接问「这些功能我不知道你是如何测试的」。

## 前提：浏览器自动化是可用的

Playwright MCP 一直可用（`mcp__plugin_playwright_playwright__browser_*`），
chrome-devtools MCP 也在。它们是 **deferred 工具**——系统提示只列名字不列 schema，
必须先 `ToolSearch` 加载。此前误以为"本项目没有浏览器工具"并写进了记忆，
导致 UI 全部用 curl 代替，等于没测。**判断工具不存在之前先搜一遍。**

## 一、API 与路由：逐条检查，不是抽查

工具：`scripts/audit/route-sweep.ts`

```bash
AUDIT_HOST=http://localhost:3100 npx tsx --env-file=.env.local \
  scripts/audit/route-sweep.ts --json docs/audit-evidence/20260802-route-sweep.json
```

枚举 `app/api` 下**全部**路由，每条查四件事：

| 检查 | 期望 | 不符合意味着 |
|---|---|---|
| 匿名访问 | 401（白名单除外） | 数据对公网开放 |
| 伪造 token | 401 | 鉴权闸门形同虚设 |
| 低权限角色（DRIVER） | 401/403；200 需人工判断 | 越权读取 |
| 授权访问 | 非 500 | 路由本身是坏的 |

⚠️ **只打 GET**。扫全部 POST/PUT/DELETE 会真的改生产数据；写路由的鉴权由前两项覆盖
（middleware 层与方法无关），业务行为由各自的端到端探针负责。

⚠️ **Next dev 是按需编译的**：一次性打 159 条路由会把编译队列冲垮，表现为 fetch
全部抛错、结果全是 `null`。脚本已带退避重试 + 路由间隔；跑的时候别同时开浏览器测试
抢编译资源，两者会互相拖垮。

## 二、UI 交互与异常状况：真的用浏览器点

**不接受**用 curl 打接口代替 UI 验证。每个前端改动至少覆盖：

### 正常路径
真实登录 → 走到目标页 → 完成操作 → **回库核对落库结果**（不是看页面提示就算过）。

### 异常路径（这是重点，也是此前完全没做的）

| 类别 | 必测 |
|---|---|
| 输入校验 | 空值、只填空格、超长、负数、小数位溢出 |
| 前置条件缺失 | 必填项没填就提交，是否有**可见**反馈 |
| 权限 | 低权限角色能否看到/点到不该碰的入口 |
| 空态 | 没数据时是空状态提示还是空白页 |
| 幂等 | 重复提交、重复确认会不会重复写 |
| 不可变约束 | 已完成的凭证能否被后续操作改掉 |

### 测 toast 类提示的坑

toast 存活时间通常 4 秒，而 MCP 工具往返可能超过这个时间——
**截图拍不到不等于没弹**。要断言提示是否出现，用
`browser_evaluate` 点击后立即查 `[data-sonner-toast]`，别靠截图。
（20260802 就因此误报过一次「点了没反应」。）

### 测 canvas 类交互

签名板这种画布交互，snapshot 里只是一个 `<canvas>`，看不出画没画上。
用 `getImageData` 数**着墨像素**来断言：

```js
const d = ctx.getImageData(0, 0, c.width, c.height).data
let inked = 0; for (let i = 3; i < d.length; i += 4) if (d[i] > 0) inked++
```

撤销/清空这类操作，断言「撤销后像素数 === 撤销前那一笔的像素数」。
⚠️ 用 `page.mouse` 画的时候，`move` 之后要确认没有残留的 pointer capture，
否则会多画出一笔，导致误判为撤销有 bug（20260802 踩过）。

## 三、探针数据一律带标记并清理

写操作探针创建的数据统一带 `AUDIT-PROBE-<日期>` 标记，
在 `finally` 里删干净，跑完核对残留数为 0。生产库不留垃圾。

## 本协议首次执行发现的问题（20260802）

| 发现 | 性质 |
|---|---|
| 实收货款 `parseFloat` 直接落库不规整，输入 `40.504050` 存成 `40.50405` | **真缺陷，已修**——分以下尾数会一路带进累计实收、司机交账、发票核销 |
| 「点客户签收没反应」 | **误报**，toast 弹了（`请先填写实收货款`），是截图时机问题 |
| 「撤销一笔有残留」 | **误报**，隔离重测 0→304→731→304 完全正确，是测试操作多画了一笔 |

两次误报都被隔离复测推翻了——**这本身说明协议里"用 evaluate 精确断言而不是靠截图"
这条是必要的**。
