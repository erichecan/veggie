## 问题

### P1 · 下架商品从常购清单**静默消失**，且名额不递补

机制（三处代码合起来才看得出）：

1. `GET /api/customer-portal/frequently-ordered` **先切 TOP 8** 再返回，且只返回
   `{productId, orderCount, lastQuantity, lastOrderedAt}` —— 不含名称/价格
2. 前端拿目录（已 `where: {status:'ACTIVE'}` 过滤）去 join：
   ```js
   const p = products.find(pp => pp.id === f.productId)
   return p ? {...} : null                       // 目录里没有 → 丢
   .filter(p => p.customerPrice != null)         // 无客户价 → 也丢
   ```
3. 于是**丢掉的名额不会由第 9、10 名递补**

实测：把常购第 1 名下架 → 清单从 8 条变 7 条，无任何提示。极端情况下 8 个常购
商品若有 5 个下架，客户看到的常购清单只剩 3 条，且完全不知道发生了什么。

对客户的实际影响：**「我常买的那个东西不见了」**，但界面不解释是缺货、下架，
还是系统坏了。

建议：接口多取一些（如 TOP 24）再由前端过滤后取前 8；被过滤掉的若属常买品，
给一条「XX 已下架」的弱提示而不是凭空消失。

### P2 · 购物车行副标题出现孤立分隔点（本次已修）

`{c.spec} · {c.uomName} · {eur(c.price)}` 无条件拼接分隔符，而 spec/uomName
多数商品为空 → 渲染成 `" ·  · €22.00"`。同文件下方的商品卡片写法是对的
（`{p.spec && <span>{p.spec} · </span>}`），照其修正。

### P3 · 商品名截断且无 tooltip

常购卡片宽 `w-40` + `truncate`，「Red Heera Peanu…」「Shimeji Mush Whi…」
看不全，鼠标悬停也没有完整名称。同名不同规格的商品（如 `340g Jar` 与
`12*340g CASE`）在截断后**完全无法区分** —— 这个场景在本库真实存在。
建议加 `title={p.name}`。

### P4 · 商品目录一次渲染 1677 张卡片

整页高 **75863px**，DOM 里 1677 个「加入购物车」按钮。无分页、无虚拟滚动。
与已知的 `/api/products` 无分页问题同源。移动端（餐厅老板多半用手机）会很吃力。

### P5 · 常购清单排序不带时间衰减

`sort((a,b) => b.orderCount - a.orderCount || …)` 纯按历史累计次数。半年前
常买、现在已不买的商品会长期占据 8 个名额中的位置。建议按「近 N 周」加权。

### P6 · 大量 €0.00 商品可加入购物车

目录里 `reuse`、`osp`、`Testing Product`、`TEST CONSUMABLE` 等显示 €0.00 且
可加购。本次是测试库数据，**需确认生产库是否也存在**——若有，客户能下出
金额为 0 的订单。
