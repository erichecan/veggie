- [x] F. 生产库 deliveryDate 缺失情况核实（部署前探针）
      验收命令：生产库 count 查询
      可看物：无
      定性状态：不涉及
      证据：SSH 生产库（167.99.86.19:2200）`SELECT status, count(*) FROM "Order" WHERE status IN
             ('CONFIRMED','WAVE_ASSIGNED','IN_DELIVERY','COMPLETED','LOCKED') AND "deliveryDate"
             IS NULL GROUP BY status` → 只有 CONFIRMED 89 条，其余四个状态 0 条。
             进一步查：CONFIRMED 总 191 条，89 条 deliveryDate 为空的 createdAt 全部落在
             2026-10-20~2026-10-21（最近一周内，生产库是 20260927 清理后重新积累的数据，
             符合"刚确认、还没被调度台排进波次"这个正常流程阶段——波次分配时才回写
             deliveryDate，见 docs 里的「波次↔deliveryDate 不变量」）。
             结论：这不是本次改动引入的风险，反而是 Module D 要解决的问题本身——这些单按旧口径
             （confirmationDate，确认时就有值）会被统计进对账单，等于对还没排车、没送达的货开账单；
             新口径（deliveryDate）正确地把它们排除在外，等排进波次回写 deliveryDate 后才会落进
             对应周期的对账单。WAVE_ASSIGNED/IN_DELIVERY/COMPLETED/LOCKED 四个"已经在途或以上"
             的状态 100% 都有 deliveryDate，说明该不变量在生产库上是成立的，没有"已派车却没日期"
             的脏数据漏网。不需要修复，部署前无阻塞项。
