1. 背景与目标

痛点：运营目前只能凭记忆和经验判断每个批次的送货路线是否合理。如果一个批次把城市南北两端的餐馆混在一起，司机会多跑很多冤枉路，但运营在排批时很难发现这个问题。

目标：

  1. 地图聚类视图 — 把每个批次的送货地址在地图上标出来，不同批次用不同颜色，运营一眼就能看到某个批次是否地理分布不合理。
  2. 路线预估 — 用 Google Maps Distance Matrix API 算出每个批次的总行驶距离和预计时间，直接显示在批次卡片上（如 "批次 A：5 家店，预计 42km / 1.5h"），让排批有数字依据。

7. 不在本期范围

  • TSP / VRP 最优路线计算 — 本期只计算已有顺序的距离，不做路线优化
  • 拖拽调整批次分配 — 不支持在地图上把某家餐馆从一个批次拖到另一个批次
  • 实时路况数据 — 使用 Distance Matrix 标准模式，不加实时路况（避免额外费用）
  • Directions API 路线画线 — 本期不在地图上画出实际行车路线，只用凸包表示范围
  • 自动批次建议 — 不自动建议"应该把 X 餐馆移到 Y 批次"

后端变更无需新增 API，复用 POST /api/distance-matrix
