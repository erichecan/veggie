## 一、现状（实查，非推测）

**先说结论：成本模型已经存在且选型是对的，缺的是数据覆盖与账务落地。**

| 环节 | 现状 |
|---|---|
| 成本存哪 | `Product.standardPrice`（商品移动加权成本）+ `Lot.unitCost`（批次成本） |
| 入库怎么算 | **已实现移动加权平均**：`newStd = (oldQty×oldStd + qty×收货价) / (oldQty+qty)`，负库存按 0 计权（`app/api/goods-receipts/route.ts:165`） |
| 出库怎么算 | **已实现 FIFO 消耗批次**（`lib/inventory.ts: consumeLotsFIFO`） |
| 毛利用哪个 | 优先「≤确认日的批次加权成本」（视图 `v_lot_daily_cost`）→ 回落 `Product.standardPrice` → `Template.standardPrice` → 0，并返回 `costedAmount` 供前端显示**成本覆盖率** |
| 外币 | PO 有 `exchangeRate` 与 `unitCostEur` 系列字段，成本回写一律读欧元字段 |

即：**加权平均（商品级）与 FIFO（批次级）并存**，且毛利分析已经知道自己的成本可能不全，
专门返回了覆盖率——这个设计是清醒的。

### 但数据侧有三个硬缺口（生产副本实测）

| 指标 | 数值 | 含义 |
|---|---:|---|
| 商品有 `standardPrice > 0` | 5004 / 5479（91.3%） | 尚可 |
| **批次总数** | **45** | ⛔ 几乎没有批次，FIFO 与批次成本形同虚设 |
| 批次有 `unitCost` | 45 / 45 | 有的都全，只是太少 |
| **SCRAP 流水** | **6 条** | ⛔ 损耗基本没被记录 |
| **JournalEntry（凭证）** | **0 张** | ⛔ 成本从未进过账 |

结合 E3 查出的「出库流水只覆盖 0.4% 的已确认订单」，实际情况是：
**成本算法是对的，但几乎没有数据流经它。**

## 二、选型建议

### 不要改算法，维持「商品级移动加权 + 批次级 FIFO」

理由：

1. 这套已经实现且互补——加权平均给出稳定的商品成本用于日常毛利，
   FIFO 保留批次可追溯性（生鲜行业按批次追溯是刚需）
2. 改成纯 FIFO 计价，要求**每一笔出库都能定位到批次**。当前批次只有 45 个、
   出库流水覆盖 0.4%，前提根本不成立
3. 改成纯加权平均，会丢掉批次追溯，与生鲜的保质期管理冲突

**该做的不是换算法，是把数据喂进去。**

### 优先级

| 序 | 动作 | 为什么排这个位置 |
|---|---|---|
| 1 | **补出库流水**（E3 已定起算日方案） | 没有出库流水，成本结转无从谈起 |
| 2 | **让收货必建批次** | 当前 45 个批次说明收货批次化没铺开；批次是 FIFO 与保质期的共同基础 |
| 3 | **损耗入成本**（见下节） | 损耗不入成本，毛利虚高 |
| 4 | 成本进账（JournalEntry） | 报表要能勾稽，但前三步没做时做这个是空转 |

## 三、损耗如何入成本

损耗目前只写 `StockMove(type=SCRAP)`，**不影响任何成本或毛利**。这会让毛利虚高。

建议口径：**损耗按发生环节计入不同科目，不摊回商品成本**。

| 环节 | 来源标记 | 建议归属 | 理由 |
|---|---|---|---|
| 收货判损 | `sourceType='RECEIPT_DAMAGE'` | **应向供应商索赔**，挂往来；索赔不成再转营业外支出 | 责任在供应商，不该抬高自家商品成本 |
| 分拣损耗 | 分拣环节的 SCRAP | 计入**营业成本**（当期费用） | 属正常经营损耗 |
| 仓储/过期 | 过期批次报废 | 计入**营业成本**，并按原因归因 | 需归因才能改善 |
| 运输损耗 | 配送环节 | 计入**营业成本**，可按司机/线路归因 | 与司机考核挂钩 |
| 客户退货 | `type='RETURN'` | 冲减收入 + 视品相决定回库或报废 | 已有 CreditNote 机制 |

**明确不做**：把损耗摊回 `Product.standardPrice`。那会让"成本"这个数同时承载
采购价和损耗率两种含义，日后任何毛利异常都无法归因。

## 五、这版不做什么

- ⛔ **不改成本算法**（加权平均 + FIFO 维持现状）
- ⛔ **不做多仓成本**（依赖 E2 的 `Warehouse` 决策，见移仓规划）
- ⛔ **不把损耗摊回商品成本**（理由见第三节）
- ⛔ **不做自动结转凭证**（凭证当前 0 张，账务体系尚未真正启用；
  在出库流水补齐之前做这个是空转）
- ⛔ **不接 Sage**（客户已明确「先做演示，等需求明确再看如何对接」）

## 六、需要业务确认

1. **收货判损的责任归属**：是先挂供应商索赔，还是直接计入营业成本？
   （影响第三节的科目设计）
2. **是否要求批次级成本核算**？若要，收货必须强制建批次并录保质期，
   会增加仓库录入负担
3. **库存资金占用按什么口径**？加权成本 × 现有量（建议），还是最近采购价 × 现有量
