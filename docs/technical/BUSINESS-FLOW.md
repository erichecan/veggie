# Veggie 餐饮供应链系统 — 完整业务流梳理

> 本文档基于客户语音描述（已纠正语音识别错误）、产品文档、以及代码实现，按日常运营的时间顺序逐步梳理。
> 每个步骤标注：**现状**（已实现）/ **缺失**（未实现或部分实现）/ **建议**（优化方向）。

---

## 系统角色一览

| 角色 | 代码 enum | 典型使用者 | 主要职责 |
|------|-----------|-----------|---------|
| 操作员 | `OPERATOR` | 主管/调度员 | 全局调度：录单、排批次、分司机、发波次、打印 |
| 销售 | `SALES` | 业务员 | 接单、录入报价、维护客户关系 |
| 餐馆 | `RESTAURANT` | 客户/餐馆老板 | 自助下单、查看历史订单 |
| 拣货员 | `PICKER` | 仓库拣货工 | 按拣货单从仓库取货 |
| 司机 | `DRIVER` | 配送司机 | 分货、核货、装车、送货、收款 |
| 老板 | `BOSS` | 企业主 | 看报表、看汇总、经营决策 |
| 财务 | `FINANCE` | 会计/出纳 | 对账、开票、佣金结算 |
| 仓管 | `WAREHOUSE` | 仓库管理员 | 收货入库、库存盘点、采购管理 |

## 一、接单阶段（每日 14:00 ~ 次日 05:00）

### 1.1 客户下单渠道

**客户语音原文（纠正后）：**
> 我们从接到订单开始，也就是从微信、WhatsApp、打电话、或者用油烟机（客户自助终端）收到订单。有些客户会通过微信群发语音或者发图片下单，业务员需要手工整理。

**业务说明：**
- 餐馆客户通过多种渠道下单：微信群、WhatsApp、电话、自助终端
- 有专门的业务员（Sales）负责对接客户，一个业务员对接多个客户
- 部分客户有固定的下单模式（每天差不多的品种和数量）

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 餐馆自助下单页面 | ✅ 已实现 | `app/[locale]/classic/restaurant/page.tsx` |
| 产品浏览、加购物车、选支付方式、提交订单 | ✅ 已实现 | 同上，含价格表引擎 |
| 客户专属价格（Pricelist） | ✅ 已实现 | `resolveCustomerPrice()` |
| 操作员手工录入报价 | ✅ 已实现 | `quotations/page.tsx` |

**缺失 / 建议：**
| 缺失项 | 说明 | 优先级 |
|--------|------|--------|
| 微信/WhatsApp 集成 | 目前无消息渠道自动解析，业务员需手工在系统中录入 | P2（长期） |
| 语音单/图片单识别 | 客户发语音或照片下单，需人工转录 | P3（AI 功能） |
| 客户常购模板 | 客户可以保存常用的购物清单，一键重下 | P2 |
| 业务员分配关系 | 客户 ↔ 业务员的绑定关系，方便查看自己的客户下单情况 | P1 |

### 1.2 业务员录入报价（Quotation）

**客户语音原文（纠正后）：**
> 业务员把客户的订单输入到系统里，先作为报价单。可能一个客户下了好几个品种，业务员要逐条录入商品、数量、单价。有些客户有自己的专属价格。

**业务说明：**
- 订单首先以"报价单"（`PENDING` 状态）进入系统
- 报价单 ≠ 正式订单，还可以修改
- 一个报价单属于一个客户，包含多个商品行
- 业务员逐条录入商品、数量、单价

## 二、确认阶段（05:00 ~ 07:00）

### 2.1 报价单确认为正式订单

**客户语音原文（纠正后）：**
> 截单时间到了以后（一般早上五点），主管把所有报价单确认，变成正式订单。确认之后客户就不能再改了。主管会看一下有没有漏单、价格有没有问题。

**业务说明：**
- 截单后，操作员批量将 `PENDING` → `CONFIRMED`
- 确认后设定 `confirmationDate`
- 确认后客户端不可修改（但操作员仍可在特殊情况下回退到 PENDING）

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 批量确认 | ✅ 已实现 | `handleBulkConfirm()` in `quotations/page.tsx` |
| 单条确认 | ✅ 已实现 | 行级操作 |
| 回退到报价（CONFIRMED → PENDING） | ✅ 已实现 | `orders/page.tsx` revert 按钮 |
| 确认日期记录 | ✅ 已实现 | `confirmationDate` 字段 |

**状态流转：**
```
PENDING (报价) ──确认──→ CONFIRMED (正式订单)
                              ↑
                              └── 可回退（操作员）
```

### 2.2 排批次与分配司机

**客户语音原文（纠正后）：**
> 确认了以后，主管要安排批次。一天可能有好几批，早上一批、中午一批、下午一批。每一批指定一个司机。主管根据订单量和客户位置来分，有些客户固定跟某个司机。有些大单可能一个司机装不下，要拆到两个批次。

**业务说明：**
- 配送批次 = `DriverSlot`（司机 + 时段 + 批次号的组合）
- 例：`1 am 张三` = 张三司机上午第 1 批
- 批次号范围：1~5，时段：am/pm
- 主管在确认订单前后都可以指定批次（报价阶段也可提前分）
- 同一天同一批次的所有订单由同一个司机配送

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 司机时段管理（CRUD） | ✅ 已实现 | `operator/drivers/page.tsx` |
| 订单分配批次（行内 dropdown） | ✅ 已实现 | `quotations/page.tsx` & `orders/page.tsx` |
| 批次分析面板 | ✅ 已实现 | `DayWiseReportDialog.tsx` → BatchCard |
| 批次重量/金额汇总 | ✅ 已实现 | 按批次统计 weight + untaxAmount |
| 未分配订单面板 | ✅ 已实现 | `UnassignedOrdersPanel` |
| 批次间转移订单 | ✅ 已实现 | transfer 功能 |
| 从批次移除订单 | ✅ 已实现 | remove 功能 |

**数据模型：**
```
DriverSlot
├── id
├── driverName ("张三")
├── timeOfDay ("am" / "pm")
├── batchNum (1~5)
└── archived (软删除)

Order.driverSlotId → DriverSlot  (FK 关联)
Order.deliveryBatch (遗留字段，向下兼容)
```

**缺失 / 建议：**
| 缺失项 | 说明 | 优先级 |
|--------|------|--------|
| 线路/区域规划 | 按客户地理位置自动建议批次分配 | P2 |
| 装载量限制预警 | 司机车辆的最大载重/体积，超出提醒 | P2 |
| 客户 ↔ 司机默认绑定 | 某些客户固定某个司机送，自动分配 | P1 |

## 三、检查库存与缺货处理（早晨 5:00 ~ 7:00）

### 3.1 库存核查

**客户语音原文（纠正后）：**
> 确认订单以后，要查一下库存够不够。有些东西可能昨天卖完了，或者今天供货商没到。缺货的品种要通知业务员，业务员再跟客户沟通，看是换品还是减量。

**业务说明：**
- 操作员/仓管需要逐批次核查：该批次的所有商品总需求量 vs 当前库存
- 缺货品种需要处理：调整订单数量、替换商品、或通知客户取消该行
- 这一步直接影响后续拣货单的准确性

## 四、打印阶段（早晨 6:00 ~ 7:00）

### 4.1 打印类型总览

**客户语音原文（纠正后）：**
> 确认完了就要打印。打印有好几种：拣货单是给仓库的，要按大货和散货分开打；送货单是每个客户一张，给司机带着送货签字用的；还有一个汇总单，就是这一批所有东西加在一起多少。

**业务说明：**
打印体系分为三种单据，入口在批次分析面板（`DayWiseReportDialog`）：

| 打印类型 | 用途 | 受众 | 分类方式 |
|----------|------|------|---------|
| **拣货单（Picking List）** | 仓库拣货依据 | 拣货员 | 按商品汇总（同一商品所有客户的需求量合计） |
| **送货单（Delivery Slip）** | 客户签收凭据 | 司机→客户 | 按客户拆分（每个客户一张） |
| **汇总单（Summary）** | 批次装车清单 | 司机/主管 | 按批次汇总所有商品总量 |

### 4.2 拣货单 — 备货清单

**详细说明：**
- 一个批次一张拣货单
- 按商品列表展示，每行是一个 SKU
- 显示：商品名称、规格、总需求量（所有客户合计）、单位
- **按 Uom.goodsType 分类**：
  - 大货（BULK）：整箱、大包装的商品
  - 散货（LOOSE）：零散、按斤称重的商品
- 拣货员按拣货单去仓库各区域取货

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 拣货单打印 | ✅ 已实现 | `_DispatchPrintClient.tsx` picking 模式 |
| 按 driverSlotId + date 查询 | ✅ 已实现 | `dispatch-loader.ts` |
| 商品按大货/散货分类 | ✅ 已实现 | `Uom.goodsType` BULK/LOOSE |
| 打印入口（批次分析面板） | ✅ 已实现 | `DayWiseReportDialog.tsx` → `buildDispatchUrl('picking')` |

### 4.3 送货单 — 每客户一张

**详细说明：**
- 按客户拆分，每个客户一张（或多张如果品种多）
- 显示：客户名、地址、电话、订单商品明细（品名、数量、单价、小计）
- 司机带着送货单去客户那里，客户签字确认
- 双语（中文 + 英文 "DELIVERY SLIP"）

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 送货单打印 | ✅ 已实现 | `_DispatchPrintClient.tsx` delivery 模式 |
| 客户信息加载 | ✅ 已实现 | `dispatch-loader.ts` 含地址、电话 |
| 订单行明细 | ✅ 已实现 | orderedQty / unitPrice / subtotal |

### 4.4 汇总单 — 批次总表

**详细说明：**
- 整个批次的所有商品汇总，类似拣货单但用于核对总量
- 司机和主管用来确认装车量是否正确

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 汇总单打印 | ✅ 已实现 | `_DispatchPrintClient.tsx` summary 模式 |

**缺失 / 建议：**
| 缺失项 | 说明 | 优先级 |
|--------|------|--------|
| 拣货单按仓库区域排序 | 按货物在仓库中的物理位置排序，提高拣货效率 | P2 |
| 送货单二维码 | 每张送货单带二维码，客户扫码确认收货 | P3 |
| 打印预览 | 打印前可在屏幕上预览，确认无误再打印 | P2 |

## 五、拣货阶段（早晨 6:30 ~ 8:00）

### 5.1 生成拣货波次（Picking Wave）

**客户语音原文（纠正后）：**
> 拣货单打好以后，仓库的人就开始拣货。一般按批次来，一个批次生成一个拣货波次。拣货的人拿着单子去各个区域拿货，拿完一样勾一样。

**业务说明：**
- 操作员在订单页面选中 CONFIRMED 订单 → 生成波次（Wave）
- 波次将订单中的商品按仓库区域（Zone）重新组织
- 一个波次可以包含多个订单，同一商品的需求量合并
- 波次状态：PENDING → PICKING → PICKED

**系统现状：**

| 单条订单生成波次 | ✅ 已实现 | `orders/page.tsx` → `generateWaveForOrder()` |
| 批量订单生成波次 | ✅ 已实现 | `orders/page.tsx` → `generateBatchWave()` |
| 波次详情（区域/商品/数量） | ✅ 已实现 | `waves/[id]/page.tsx` |
| 订单状态 → WAVE_ASSIGNED | ✅ 已实现 | 生成波次时自动更新 |

### 5.2 执行拣货

**业务说明：**
- 拣货员在自己的页面看到待拣的波次列表
- 进入波次详情，逐个区域、逐个商品拣货
- 每拣完一个商品，填入实际拣货数量，勾选完成
- 支持"全部标记完成"的批量操作

## 六、司机分货、核货与装车（08:00 ~ 09:00）

### 6.1 司机按客户分拣

**客户语音原文（纠正后）：**
> 拣完以后就是分货。拣货是按品种拣的，一个品种可能要分给好几个客户。分货就是把每个客户的东西放到一起，一家一堆。分完以后每堆贴上客户名字的标签。

**业务说明：**
- 拣货是"按商品"聚合的；分货是"按客户"分发的
- **实际操作中，司机自己负责分货，没有单独的分货员角色**
- 司机来到仓库后，看到已拣完的波次（PICKED 状态），按自己批次的客户逐个分拣
- 逐个商品 → 按客户分配数量
- 分完后波次状态变为 SORTED

**系统现状：**
| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 分货页面（司机使用） | ✅ 已实现 | `sorter/page.tsx`（系统中标记为 sorter 页面，但实际由司机操作） |
| 分货操作页面 | ✅ 已实现 | `sorter/sort/[waveId]` |
| 排序管理（操作员视角） | ✅ 已实现 | `operator/sorting/page.tsx` |

**状态流转：**
```
Wave: PICKED ──司机开始分货──→ SORTING ──分货完成──→ SORTED
```

### 6.2 司机核货

**客户语音原文（纠正后）：**
> 分好以后司机来核货。司机拿着汇总单，一样一样对，数量对不对、品种对不对。有时候还要称重，大货称总重，散货一样一样称。核完没问题就装车。

**业务说明：**
- 司机到仓库后，用汇总单逐项核对
- 核对的是实际分好的货物 vs 送货单上的数量
- 核对完成后装车出发

| 功能 | 状态 | 代码位置 |
|------|------|---------|
| 司机配送列表 | ✅ 已实现 | `driver/page.tsx` — trip 列表 |
| 汇总单打印 | ✅ 已实现 | dispatch summary 打印 |

## 附录：核心数据模型关系图

```
Customer ──1:N──→ Order ──1:N──→ OrderLine ──N:1──→ Product
    │                │                                   │
    │                ├── driverSlotId → DriverSlot        ├── templateId → ProductTemplate
    │                │                                   │                    │
    │                ├── createdById → User (业务员)       │                    ├── uomId → Uom
    │                │                                   │                    │    └── goodsType (BULK/LOOSE)
    │                └── waveId → PickingWave             │                    │
    │                        │                           │                    └── type (PRODUCT/CONSU/SERVICE)
    │                        ├── zones[] → Zone           │
    │                        │    └── items[]             │
    │                        └── status (PENDING→SORTED)  │
    │                                                     │
    └── pricelistId → PriceList ──→ PriceRule ──→ 客户专属价格

DriverSlot
├── driverName
├── timeOfDay (am/pm)
├── batchNum (1~5)
└── 一天一个批次 = 一组待配送订单

Trip (配送行程)
├── driverName
├── timeSlot
├── restaurants[] (送货目标)
└── totalPayment (收款总额)
```
