一、日常运营时间线

从下午接单到次日配送的完整一天工作流程
14:00 ~ 次日 05:00
客户下单 / 业务员录单
餐厅通过小程序、微信、WhatsApp、电话等渠道下单，业务员在系统中逐条录入商品、数量、单价，订单状态为 PENDING
05:00
截单
系统自动截单，不再接收新的报价单
05:00 ~ 07:00
操作员确认订单 · 排批次 · 分配司机 · 检查库存
操作员逐单审核，确认后状态变 CONFIRMED；创建 DriverSlot 配送批次绑定司机；检查库存是否充足，处理缺货
07:00
打印拣货单 · 送货单 · 汇总单
三种单据：拣货单（按商品汇总给拣货员）、送货单（按客户分给司机和客户）、汇总单（按批次汇总），大货 BULK 和散货 LOOSE 分开打印
07:00 ~ 09:00
仓库拣货
拣货员按拣货单从货架取货，按商品汇总提高效率，大货散货分开拣对应不同区域
08:00 ~ 09:00
司机分货 · 核货 · 装车
司机自己按送货单将货物按客户分装（没有专门分货员），核对数量确认无误后装车
09:00 ~ 下午
按路线配送 · 客户签收
司机按路线依次配送，客户核对签收，退换货当场处理，司机当场收款（现金客户）
配送结束后
收款对账 · 财务核销
司机交账，财务定期对账，月结客户统一结算

二、接单阶段（14:00 ~ 次日 05:00）

餐厅下单 → 业务员录入 → 系统生成报价单
我们从接到订单开始，也就是从微信、WhatsApp、打电话、或者用油烟机（客户自助终端）收到订单。有些客户会通过微信群发语音或者发图片下单，业务员需要手工整理。

客户下单渠道

📱 多渠道接单

  • 餐馆客户通过微信群、WhatsApp、电话、自助终端等多种渠道下单
  • 有专门的业务员（Sales）负责对接客户，一个业务员对接多个客户
  • 部分客户有固定的下单模式（每天差不多的品种和数量）
  • 系统支持客户专属报价单（Pricelist），不同客户价格可以不同

业务员录入报价

业务员把客户的订单输入到系统里，先作为报价单。可能一个客户下了好几个品种，业务员要逐条录入商品、数量、单价。有些客户有自己的专属价格。

📋 报价单说明

  • 订单首先以"报价单"（PENDING 状态）进入系统
  • 报价单 ≠ 正式订单，还可以修改
  • 一个报价单属于一个客户，包含多个商品行
  • 05:00 自动截单，不再接收新的报价单

三、确认阶段（05:00 ~ 07:00）

操作员审核报价单 → 确认为正式订单
截单时间到了以后（一般早上五点），主管把所有报价单确认，变成正式订单。确认之后客户就不能再改了。主管会看一下有没有漏单、价格有没有问题。

✅ 确认流程

  • 截单后，操作员逐单审核检查商品数量和价格
  • 可修改订单内容后再确认
  • 批量将 PENDING → CONFIRMED，记录确认日期
  • 确认后客户端不可修改，但操作员可在特殊情况下回退到 PENDING
  • 所有操作记录操作日志

四、排批次与分配司机（05:00 ~ 07:00）

创建配送批次 → 绑定司机 → 订单分配到批次
确认了以后，主管要安排批次。一天可能有好几批，早上一批、中午一批、下午一批。每一批指定一个司机。主管根据订单量和客户位置来分，有些客户固定跟某个司机。

🚚 DriverSlot 配送批次模型

  • 配送批次 = DriverSlot（司机 + 时段 + 批次号的组合）
  • 例：1 am 张三 = 张三司机上午第 1 批
  • 批次号范围：1~5，时段：am / pm
  • 同一天同一批次的所有订单由同一个司机配送
  • 订单分配到批次后状态变为 WAVE_ASSIGNED
  • 支持拖拽调整、批次间转移
DriverSlot ├── id ├── driverName ("张三") ├── timeOfDay ("am" / "pm") ├── batchNum (1~5) └── archived (软删除) Order.driverSlotId → DriverSlot (FK 关联)

五、检查库存与缺货处理（05:00 ~ 07:00）

核查库存 → 处理缺货 → 修改订单
确认订单以后，要查一下库存够不够。有些东西可能昨天卖完了，或者今天供货商没到。缺货的品种要通知业务员，业务员再跟客户沟通，看是换品还是减量。

📊 库存检查要点

  • 操作员/仓管需要逐批次核查：该批次总需求量 vs 当前库存
  • 显示当前库存量、已分配量、可用量
  • 缺货时可修改数量、替换商品或联系客户取消
  • 低库存预警阈值：20
  • 慢动品检测：3 天无销售自动标记

六、打印阶段（07:00）

拣货单 · 送货单 · 汇总单，三种单据按需打印
确认完了就要打印。打印有好几种：拣货单是给仓库的，要按大货和散货分开打；送货单是每个客户一张，给司机带着送货签字用的；还有一个汇总单，就是这一批所有东西加在一起多少。
打印类型用途受众分类方式
拣货单
Picking List		 仓库拣货依据 拣货员 按商品汇总（同一商品所有客户的需求量合计），大货 BULK / 散货 LOOSE 分开
送货单
Delivery Slip		 客户签收凭据 司机 → 客户 按客户拆分（每个客户一张），含品名、数量、单价、小计
汇总单
Summary		 批次装车清单 司机 / 主管 按批次汇总所有商品总量

🖨 打印说明

  • 所有打印入口在批次分析面板中，支持按批次打印
  • 大货（BULK）和散货（LOOSE）分开打印，对应仓库不同区域
  • 送货单支持双语（中文 + 英文 "DELIVERY SLIP"）

七、仓库拣货（07:00 ~ 09:00）

生成拣货波次 → 拣货员按单从各区域取货
拣货单打好以后，仓库的人就开始拣货。一般按批次来，一个批次生成一个拣货波次。拣货的人拿着单子去各个区域拿货，拿完一样勾一样。

📦 拣货流程

  • 操作员选中 CONFIRMED 订单，生成拣货波次（Wave）
  • 波次将订单中的商品按仓库区域（Zone）重新组织
  • 按商品汇总提高效率——同一商品的需求量合并
  • 大货和散货分开拣，对应仓库不同区域
  • 拣货员逐项填入实际拣货数量，勾选完成
  • 支持"全部标记完成"的批量操作
  • 完成后波次状态变为 PICKED

八、司机分货、核货与装车（08:00 ~ 09:00）

司机按客户分装 → 核对数量 → 装车出发
拣完以后就是分货。拣货是按品种拣的，一个品种可能要分给好几个客户。分货就是把每个客户的东西放到一起，一家一堆。分完以后每堆贴上客户名字的标签。

⚠️ 重要：没有专门的分货员

  • 在爱尔兰的实际业务中，司机自己负责分货
  • 司机来到仓库后，按自己批次的客户逐个分拣
  • 拣货是"按商品"聚合的，分货是"按客户"分发的
分好以后司机来核货。司机拿着汇总单，一样一样对，数量对不对、品种对不对。有时候还要称重，大货称总重，散货一样一样称。核完没问题就装车。

九、配送（09:00 ~ 下午）

按路线逐家配送 → 客户签收 → 收款
司机就按路线一家一家送。到了客户那里，客户验货、签字。有些客户是现金结，司机当场收钱；有些是月结的，不用收钱。

🚛 配送流程

  • 司机按 Trip 中的客户列表逐家配送
  • 每送完一家，在系统中标记"已送达"
  • 客户核对商品后签收
  • 退换货当场处理
  • 配送完成后状态变为 COMPLETED

十、收款与对账

司机交账 → 财务对账 → 月结客户结算
司机送完回来要交账。现金收了多少，哪些客户签了单。财务每天要对一下，现金的当天清，月结的记到客户欠款里。到了月底，月结客户要催款和对账。

💰 收款对账流程

  • 支持现金、转账、月结三种收款方式
  • 司机当场收款后录入系统
  • 财务定期对账，核对现金与系统记录
  • 月结客户月底统一结算，出具对账单
  • 销售佣金自动计算

十一、采购与入库

采购计划 → 供货商送货 → 验收入库
另外一条线就是采购。看库存不够了，或者预计明天要用多少，就跟供货商下采购单。供货商送到以后要验收入库。

📥 采购流程

  • 根据订单需求和库存情况制定采购计划
  • 向供货商下采购订单
  • 供货商送到后验收入库，记录批次、数量、成本价
  • 库存实时更新，支持盘点
采购状态: DRAFT → SENT → CONFIRMED → RECEIVED → INVOICED ↘ CANCELLED
