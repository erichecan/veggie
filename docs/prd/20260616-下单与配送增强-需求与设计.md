# 下单与配送增强 — 需求与设计

> 日期：2026-06-16 · 项目：veggie / North Fresh
> 本文记录用户提出的 6 条需求、与现有代码的逐条对照、以及本次实际开发范围与设计。

---

## 一、用户原始需求

1. 下单时要能够提醒低库存。
2. 下单时要能够提醒商品重复了 —— 客户下单时也可能忘记（例：先说一袋洋葱，中间说了很多别的，最后又说一袋洋葱），录单时要提醒。
3. 批量确认的 quotation 不再在报价单列表显示，要转到销售单列表显示。
4. 刚确认且未分配司机的销售单，应出现在配送调度工作台左侧的「待分配订单」。
5. 销售单列表中的「打印」按钮要能区分已打印 / 未打印的订单；已打印的订单后面要显示打印时间、打印人。
6. 在配送调度台把销售单拖拽到司机名下，编辑每车的托盘备货情况，调整后可打印拣货单（给拣货人员看，能看到每个司机的订单、每个托盘的货）。

## 三、确认的范围（用户已拍板）

- **提醒覆盖入口**：快速下单页 `place-order` + 报价单页的「粘贴文本批量下单」。
- **重复商品提醒方式**：顶部 banner 提示 +高亮重复行（非阻断，由操作员决定合并或保留）。
- **销售单打印对象**：送货单（delivery note）+ 销售单 / 订单确认单两种，均需记录已打印状态。

## 四、设计

### 需求 2 — 重复商品提醒

**place-order（`place-order/page.tsx`）**
- 用 `useMemo` 按 `productId` 对 `lines` 分组计数，得到 `duplicateMap`（productId → 出现次数）。
- 顶部新增提示 banner（与现有低库存 banner 同区域、同风格）：「⚠️ 重复商品：「洋葱」出现 2 次」，列出所有重复商品。
- 重复行加视觉高亮（行背景 / 左边框警示色）。
- 纯前端、非阻断，不改下单提交逻辑。

**报价单粘贴下单（`quotations/page.tsx` 的批量下单解析）**
- 解析文本为 items 后，按 `productId`（或归一化 `productName`）检测重复。
- 在解析结果预览处给出重复提示，重复项高亮，让操作员确认后再提交。

### 需求 5 — 销售单打印状态追踪

**数据模型（`prisma/schema.prisma`，`Order`）**
```prisma
printedAt     DateTime?   // 最近一次打印时间
printedById   String?     // 打印人用户 ID
printedByName String?     // 打印人姓名快照
printType     String?     // 最近一次打印的单据类型：DELIVERY | SALES
printCount    Int @default(0)  // 累计打印次数
```
- 迁移：`npx prisma migrate dev --name order_print_tracking` + `npx prisma generate`。

**API（写操作，必须鉴权）**
- 新增 `POST /api/orders/[id]/mark-printed`，body `{ type: 'DELIVERY' | 'SALES' }`。
- `withAuth` 校验 → 更新 `printedAt=now`、`printedById/Name`=当前用户、`printType=type`、`printCount++`。
- 写 `ActionLog` 审计。

**销售单列表（`orders/page.tsx`）**
- 新增「打印」操作（按钮 / 下拉）：可选「送货单」或「销售单确认单」。
  - 送货单：复用 / 参数化现有单订单打印视图 `print/[id]`（执行阶段确认是否需 `?type=delivery`）。
  - 销售单确认单：复用现有 `print/[id]`。
- 打开打印窗口的同时调用 `mark-printed` 记录状态。
- 列表新增「打印状态」列：
  - 未打印 → 灰色「未打印」徽标。
  - 已打印 → 绿色「已打印 ✓」+ 打印时间 + 打印人（次数 > 1 时显示 ×N）。

### 需求 1/3/4/6 — 端到端验证（不重做）

起本地服务，用现有种子数据走通：
- **需求1**：place-order 选一个低库存 / 负库存商品 → 出现 ATP toast + 顶部 banner。
- **需求3**：报价单列表批量选中 → 批量确认 → 报价单列表中消失，销售单列表（orders）中出现且状态为 Sales Order。
- **需求4**：调度台「批次管理」tab → 左侧「待分配」竖条含刚确认、未入批的销售单。
- **需求6**：把待分配订单拖到司机批次 → 打开托盘编排 → 调整托盘 → 打印拣货单（PickSheetModal），核对能看到司机的订单与每盘的货。

## 六、风险点

- **打印「送货单 vs 销售单」是否需要两套模板**：现有 `print/[id]` 为单订单打印，需在执行阶段确认其内容是否同时满足两种单据，或是否需加 `?type` 参数 / 新视图。
- **打印状态的「最近一次」语义**：多次打印只保留最近一次 + 计数；如需保留完整打印历史需另建表（本次不做，YAGNI）。
- **报价单粘贴下单的重复判定口径**：优先用 `productId`；当行未匹配到商品（仅文本）时退化为归一化 `productName` 比较。
- **已实现需求的验证依赖种子数据质量**：需保证种子中存在低库存商品、PENDING 报价单、CONFIRMED 未入批订单、已配置司机批次。
