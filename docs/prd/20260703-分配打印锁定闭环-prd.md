# 分配完成 → 打印可见 → 拣货锁定闭环 —— 需求与设计

> 日期：2026-07-03
> 分支：`feat/dispatch-print-lock`
> 状态：已确认，待实现

---

## 一、背景与目标

调度在给每单分配司机、把批次「分配完成」后，仓库要能提前开始拣货（不必等司机发车）。拣货一旦开始，订单内容必须冻结——避免"仓库正在拣，调度又改单"的混乱。若拣货中发现缺货，由打印员在缺货处理 tab 直接改量，改完重打拣货单。

本次交付四件事：

- **A. 司机卡片三值**：调度台司机卡片显示件数、重量、金额，便于调度判断是否调整。
- **B. 分配完成即可见**：调度点「分配完成」后，打印员在打印中心就能看到并打印该批次（时机提前到发车之前）。
- **C. 拣货锁定闭环**：打印员点「打印拣货单」→ 该批次锁定，调度改不了；打印员可「解锁」，解锁后调度可改、改完重打重新锁定。
- **D. 缺货可改量**：打印员在缺货处理 tab 可改数量/删行（锁定的唯一例外），改完重打拣货单。

## 二、名词与既有事实

- **批次 / wave**：`PickingWave`，调度单一真相 `orderIds[]`。销售单列表改司机（`/api/orders/[id]/batch`）与调度台拖拽（`/api/waves/[id]/assign`）写的是同一份 `PickingWave.orderIds`（见 `lib/wave-assign.ts`，SSOT 已于 `docs/20260624` 统一）。因此**销售单列表键盘选司机 = 调度台拖拽**，无需重复操作。
- **批次阶段**（`lib/wave-stage.ts`，既有）：`assigning`（分配中）→ `assignment_done`（分配完成，`assignmentDoneAt`）→ `in_transit`（在途，`dispatchedAt`）→ `completed`（`completedAt`）。
- **确认出发**：回填订单 `deliveryDate`=排程日、订单转 `IN_DELIVERY`、批次 `dispatchedAt`。
- `Order.lockedAt`：**开票锁定**语义，本次不复用。
- `OrderLine` 三个数量：`orderedQty`（客户下单量，账目基准，`subtotal=unitPrice×orderedQty`）、`deliveredQty`（已交货）、`invoicedQty`（已开票）。
- 税务 SSOT：`totalAmount` 税前、`taxRate` 百分数、`subtotal` 恒 `=unitPrice×orderedQty`（见 `docs/20260701`）。

## 三、核心模型：两个正交维度

| 维度 | 字段 | 含义 | 谁改 |
|------|------|------|------|
| 阶段 | `assignmentDoneAt` / `dispatchedAt` / `completedAt` | 进行到哪一步 | 调度 |
| 锁定 | `pickLockedAt`（新增） | 内容能不能改 | 打印员（打印拣货单时上锁 / 手动解锁） |

主链路：
```
分配中 ──[调度"分配完成"]──▶ 分配完成 ──[打印员"打印拣货单"]──▶ 已锁定(拣货中)
   ▲                          │(打印中心可见/可撤销)         │(调度改不了)
   └────[打印员"解锁"]─────────┴───────────────────────────────┘
                                                  │
        缺货：打印员缺货tab改量/删行(锁定例外) ──▶ 重打拣货单(重新锁定)
                                                  │
                          [调度"确认出发"] ──▶ 在途(独立一步，不受锁定影响)
```

## 四、Feature A — 司机卡片三值

**现状**：`BatchTab.tsx` 的 `Lane` 卡片显示 `批次N · X单 · Y家 · €金额`（`laneMetrics()` 只算单数/家数/金额）。

**目标**：改为 `批次N · X单 · Z件 · W kg · €金额`。

- 件数 `itemCount` = 该批次所有订单行 `orderedQty` 之和。
- 重量 `weight` = Σ(`orderedQty` × 商品 `template.weight`)，单位 kg，保留 1 位小数。
- 金额 = 现有口径不变（`totalAmount`，税前）。
- 保留「X单」，去掉「Y家」。

**数据加载**：`BatchTab` 的订单请求从 `include_lines=false` 改为 `include_lines=true`，取到订单行与 `product.template.weight`（与打印中心 `lineWeight` 同源）。

**验收**：
- 任一有单批次卡片显示 4 段：单数、件数、kg、金额。
- 件数/重量/金额随拖拽增减实时变化。
- 商品无重量时按 0 计，不报错。

## 五、Feature B — 分配完成即可见（打印中心换数据源）

**现状**：`PrintCenter.tsx` 按 `deliveryDate` 拉单（`status=CONFIRMED,WAVE_ASSIGNED,IN_DELIVERY&dateField=deliveryDate`）。`deliveryDate` 只在「确认出发」时回填 → 出发后才可见。

**目标**：打印中心改为**按批次阶段**取数：拉当日批次中 `assignmentDoneAt != null 或 dispatchedAt != null`（即阶段 ≥ 分配完成、未完成）的 wave，再展开其 `orderIds` 对应订单。→ 分配完成即可见。

**实现要点**：
- 每张批次卡片 = 一个 wave，卡片持有 `wave.id`（锁定/解锁要用）。
- 取数：`GET /api/waves?date=` 得当日 waves，按阶段过滤；再取这些 wave `orderIds` 的订单（`include_lines=true`，用于件数/重量/金额与拣货明细）。
- 分组由"从订单反推 driverSlot 字符串"改为"直接以 wave 为组"，与调度台卡片一一对应。
- 未到分配完成的批次不进打印中心。
- 保留现有 AM/PM 分区、司机/时段/批次筛选、排序、汇总。

**验收**：
- 调度点「分配完成」后刷新打印中心，该批次出现且可打印；撤销分配完成后消失。
- 已出发（在途）批次仍可见，可重打。
- 未分配完成的批次不出现。

## 六、Feature C — 拣货锁定 / 解锁 / 重打

### 数据模型
`PickingWave` 新增：
- `pickLockedAt   DateTime?`
- `pickLockedById String?`
- `pickLockedByName String?`

### 上锁
- 打印员在打印中心点某批次「拣货单」→ 打开打印页 **并** `POST /api/waves/[id]/pick-lock { locked: true }`（写 `pickLockedAt`=now、打印人）。
- 「全部打印拣货单」= 对所有可见批次批量上锁。
- 只有「拣货单」触发锁定；「订单」「汇总单」不锁。

### 锁定后拦截（服务端强制）
锁定批次涉及的写操作返回 **409** + 明确文案（前端 toast「该批次拣货中已锁定，请找打印员解锁」）：
- `PUT /api/waves/[id]/assign`、`/unassign`（源或目标 wave 被锁则拒）
- 批次间移动（`moveWave` 两步任一命中被锁 wave）
- `PUT /api/orders/[id]/batch`（销售单列表改司机，若会加入/移出已锁 wave）
- `PUT /api/waves/[id]/assignment-done { done:false }`（撤销分配完成）

**不拦截**：
- `PUT /api/waves/[id]/dispatch`（确认出发，独立一步）
- 打印员缺货改量（Feature D，锁定的唯一例外）

> 锁定校验抽成一个共享 helper（如 `assertWaveNotPickLocked(waveId)`），assign/unassign/batch 三个入口统一调用，避免漏口。

### 解锁
- 打印中心被锁批次卡片显示 `🔒 拣货中` 徽章 + 「解锁」按钮 → `POST /api/waves/[id]/pick-lock { locked:false }`（清 `pickLockedAt`）。
- 解锁后调度可改；改完打印员重打拣货单 → 重新上锁。

### 调度台呈现
- 被锁批次的 `Lane` 卡片显示 `🔒 拣货中` 徽章，卡片内订单不可拖、`分配完成/撤销` 按钮置灰（`确认出发` 仍可用）。
- 需在 `/api/waves?date=` 返回体带上 `pickLockedAt`，前端据此置灰。

**验收**：
- 打印拣货单后，调度台该批次拖拽被拒、按钮置灰；销售单列表改该单司机返回 409。
- 打印员解锁后，调度可正常改；改完重打恢复锁定。
- 锁定期间「确认出发」正常。
- 未打印拣货单的批次不受影响。

## 七、Feature D — 缺货处理可改量 / 删行

**现状**：`ShortageHandler.tsx` 只读（`GET /api/waves/[id]/shortage` 展示缺哪些货、缺多少），无写操作。

**目标**：打印员可对缺货行**改数量（≤ 下单量）或删行**，即使批次已锁定也可改（锁定的唯一例外）。

### 落库口径
改 **`orderedQty`**（下单量即账目基准），单一数量 SSOT、账目自动一致：
1. 更新 `OrderLine.orderedQty`（删行=删除该 `OrderLine`）。
2. 重算行 `subtotal = unitPrice × orderedQty`。
3. 重算订单 `totalAmount` / `subtotal` 等汇总（遵守税务 SSOT）。
4. 把少供差额 `(旧orderedQty − 新orderedQty)` **退回 `Product.qtyOnHand`**（确认订单已扣，缺货即改正过扣）。
5. 写审计日志（`OrderAuditLog` / `action-log`）。

> **必须复用现有订单编辑的重算 + 退库路径**（订单详情改行时已有该逻辑），不另写一套，避免与税务/库存 SSOT 打架。实现前先定位现有 helper。

**备选（未采纳）**：写 `deliveredQty` 保留 `orderedQty`——概念更纯，但要求拣货单/送货/开票统一改判优先读 `deliveredQty`，且与 Trip 送达回写打架，改动面更大。故选改 `orderedQty`。

### 交互
- 缺货 tab 每个缺货商品下列出受影响订单行，打印员可就地改数量或删行，保存。
- 改完提示"可重打拣货单"。
- 锁定批次也允许此操作（唯一例外）。

**验收**：
- 打印员改某行数量→订单金额、库存、审计日志同步更新，`subtotal` 与税务 SSOT 一致。
- 删行→该行消失、金额与库存正确回退。
- 锁定批次仍可在缺货 tab 改量。
- 改后重打拣货单显示更新后数量。

## 八、数据模型变更汇总

`PickingWave` 新增 3 个可空字段：`pickLockedAt` / `pickLockedById` / `pickLockedByName`。

迁移按项目惯例：`db push` + 手写迁移 SQL + `prisma migrate resolve`（规避 shadow DB 重放旧迁移失败，见 `docs` 既往记录）。无破坏性变更，无需数据回填。

## 九、接口清单

| 接口 | 变更 | 说明 |
|------|------|------|
| `POST /api/waves/[id]/pick-lock` | 新增 | `{locked:boolean}`，打印员上锁/解锁，鉴权必需 |
| `PUT /api/waves/[id]/assign` | 改 | 命中被锁 wave → 409 |
| `PUT /api/waves/[id]/unassign` | 改 | 同上 |
| `PUT /api/orders/[id]/batch` | 改 | 若动到被锁 wave → 409 |
| `PUT /api/waves/[id]/assignment-done` | 改 | 被锁时禁止 `done:false` |
| `GET /api/waves?date=` | 改 | 返回体加 `pickLockedAt` |
| `POST /api/waves/[id]/shortage-adjust`（或按行接口） | 新增 | 打印员改量/删行 + 重算 + 退库 + 审计 |

所有写接口沿用现有 `withAuth` 鉴权。

## 十、非目标（本次不做）

- 「申请解锁」审批/通知流（本次调度口头找打印员，打印员手动解锁即可）。
- 缺货写 `deliveredQty` 方案。
- 司机卡片金额税前/税后切换（沿用现有税前口径）。
- 拣货员独立账号/角色（仍由打印员代操作）。

## 十一、风险点

1. **打印中心换数据源**（B）改动面最大，锁定/缺货后重新拉数要保持一致。
2. **缺货改量**（D）牵动金额与库存，最需谨慎——必须复用现有订单编辑重算+退库路径。
3. **锁定拦截**要覆盖调度台与销售单列表两个写入口，抽共享 helper 防漏。
