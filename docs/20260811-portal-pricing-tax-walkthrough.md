## 查出并修复的两个问题

### P0 · 门户下单的订单行**税率全部为空**（少计税）

实测分布：

| 订单来源 | 行数 | 有税率 | 税率为空 |
|---|---:|---:|---:|
| **PORTAL** | 5 | **0** | **5** |
| INTERNAL | 1446 | 1444 | 2 |

根因在 `lib/server-pricing.ts` —— 这个函数号称「服务端权威定价」，但**只有价格是权威的**：

```ts
taxRate: item.taxRate != null && … ? … : item.taxRate   // 完全取自客户端提交
```

而餐馆门户压根不传这个字段，于是门户下的每一单税率都是 NULL。

**后果不是显示难看，是开票时按 0 计税。** 该客户税率 13.5%，一单 €418.55 就少算
€56.50 的 VAT。

修法：客户端没传时回落到商品档案的 `customerTaxRate`（第 329 行早就查出来了，
只是没用）。量纲统一由新增的 `normalizeTaxRate()` 收口 —— 商品档案存小数
（0.1350），OrderLine 存百分数（13.5），两个来源必须在同一处归一。

验证：修复后新建门户单，两行分别落 `13.5` 与 `20.0`，符合 SSOT。

### P1 · 门户全程不标注税前/税后

系统的价格口径一律**税前**（`unitPrice`、`totalAmount` 都是，见 `docs/20260701`）。
但门户此前：

- 商品卡片 €22.00 —— 无标注
- 购物车「合计 €661.00」—— 无标注
- 订单详情「合计 €418.55」—— 无标注，`taxRate` 字段取了却从未渲染

餐厅看到 €22.00，实际会被按 €24.97 开票（13.5% VAT）。**差额不小且毫无提示。**

修法（购物车 + 订单详情页一致处理）：

```
合计（不含税）  €4.20
税额            €0.57
含税应付        €4.77     ← 加粗突出
```

下单按钮与成功提示也一并改成含税金额 —— 此前按钮显示税前额，紧贴着「含税应付」
很容易误读成要付的钱。
