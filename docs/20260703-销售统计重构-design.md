# 销售统计（日销售管理中心·第三 Tab）重构设计

日期：2026-07-03
状态：已与用户确认，待实现

## 背景与问题

当前 `SalesStats.tsx` 把三件事摞在一个 Tab 里，彼此不一致：
1. 重筛选栏（日期/业务员/分类/司机/AM-PM/批次/客户/商品）
2. 筛选结果表（日期→客户→商品，打印报表预览）
3. 今日总量（调度：按分类看量+库存）
4. 周趋势（销售员：按星期看量）

实测三个视图来自**三个独立的订单请求**、日期口径各不相同，筛选栏基本只服务 ②，③④ 大部分无视筛选栏，③ 还自带一套重复的分类选择器。

## 目标模型（用户确认：方案 A）

一套区间日期 + 一套筛选 → 筛出一批订单行 → 下面切换不同"查看方式"展示同一批数据。

```
[ 筛选栏 ] 日期区间 From–To · 分类(多选) · 商品 · 客户 · 司机/时段/批次 · 业务员
        ↓ 一次请求，前端统一过滤
[ 结果 ] 查看方式：按客户 | 按商品 | 按分类 | 按星期趋势
```

## 四种查看方式

| 方式 | 分组 | 列 | 服务 |
|---|---|---|---|
| 按客户 | 日期→客户→商品 | 数量/单价/金额 + 日小计 + 总计 | 运营对账/打印 |
| 按商品 | 每商品汇总 | 客户数/数量/均价/金额，按金额降序 | 通用 |
| 按分类 | 分类→商品 | 单位/数量/ATP库存(零黄负紫,带图例) | 调度备货 |
| 按星期趋势 | 周一~周日柱状 | **日均**数量(可切金额) | 销售员订货 |

- **按星期趋势用「日均」**：每个星期几 = 区间内该星期几各天的平均值（sum / 该星期几在区间内出现的天数）。区间拉多长都不撑大数字，直接反映"典型周一走多少"。
- **ATP** = 商品当前 qtyOnHand − 区间内该商品总需求量。单日（From=To）时最精确，是调度主用法。

## 数据流（关键简化）

- **3 个请求 → 1 个**：只按 `status=CONFIRMED,WAVE_ASSIGNED,IN_DELIVERY,COMPLETED & dateField=deliveryDate & fromDate..toDate & include_lines`。
- **全部筛选前端做**：分类(多选,用 productMap.categoryId)、商品、客户、司机/时段/批次、业务员(order.salesUserId)。分类因此天然支持多选。
- 分类名/ID 来自 `productMap`（allProducts，含 category/categoryId，已于本日修复 /api/products 返回分类）。

## 筛选栏变化

- 分类：单选下拉 → **多选 chips**（调度可一次选 3-4 个分类）。
- 其余筛选保留。

## 删除项

1. 隐藏的 dashboard 块（`{false && …}`，约 230 行）及只服务它的 state/memo：dashPeriod/dashFrom/dashTo/dashOrders/dashGranularity/showCategoryOverlay、productTop10/categoryTop10/customerTop10/weekdayData/chartData/topCategories。
2. `dailyOrders`/`dashOrders` 两个额外请求及其日期推算 effect。
3. 今日总量内部的 `selectedStatsCats` 分类 chips。
4. 两个割裂的切换（reportGroupBy 的按客户/按商品 + statsView 的今日总量/周趋势）→ 合并为一个四选一 viewMode。

## 打印

保留现有三种 day-wise-report 打印（日报/明细/商品×星期汇总）+ 按分类打印，打印的都是当前筛选结果。
