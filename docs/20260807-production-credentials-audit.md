# 生产账号凭据审计（2026-08-07）

> 起因：用户问「系统用户里只有 3-4 个人的规模，这个不对」以及「应该取消自动登录」。
> 第一个问题是误会（生产实际有 51 个账号，见下），第二个问题查下去牵出一串真问题。

---

## 1. 「只有 3-4 个人」是误会，但查的过程有价值

生产库实测 **51 个账号**，接口 `GET /api/users` 也确实返回 51 条：

| role | 账号数 |
|---|---:|
| DRIVER | 23 |
| OPERATOR | 21 |
| RESTAURANT | 2 |
| BOSS / FINANCE / WAREHOUSE / SORTER / PICKER | 各 1 |

「3-4 个」应该是看到了开发过程中一次性测试库的截图（那里只有 3 个临时账号）。
数据没丢，迁移没问题。

---

## 2. ⛔ 查出来的真问题：全部 51 个账号都是弱口令，且明文在 git 里

| 类别 | 账号数 | 密码 | 出处 |
|---|---:|---|---|
| 真实员工（gmail / hotmail / veggie.local 等） | 42 | `test123` | `scripts/import-users.ts:51`、`scripts/import-drivers.ts:44` |
| 种子演示账号（`*@veggie.com`） | 9 | `Demo1234!` | `prisma/seed.ts:27` |

**实测确认（生产站，只做登录、无任何写操作）**：

```
boss@veggie.com      / Demo1234!  → ✅ 登录成功，role=BOSS
operator@veggie.com  / Demo1234!  → ✅ 登录成功，role=OPERATOR
finance@veggie.com   / Demo1234!  → ✅ 登录成功，role=FINANCE
driver.moazzam@veggie.local / test123 → ✅ 登录成功，role=DRIVER
```

42 个真实账号只有 **6 个不同的 bcrypt 哈希** —— bcrypt 每次加盐结果都不同，
出现重复只能是导入脚本算一次哈希、复制给一整批人。

### 2.1 登录页曾把管理员入口直接摆在外面

`/enter` 上原有「一键登录」6 个按钮，密码 `Demo1234!` 写死在前端代码里，
点一下就以 BOSS 身份进入系统。**已于 20260807 移除**（本次提交），
只保留邮箱 + 密码表单。

⚠️ **移除按钮不等于账号安全了** —— 账号还在，密码还是那个，知道邮箱的人照样进得来。

### 2.2 登录接口没有速率限制

连打 8 次错密码，全部返回 401，没有 429、没有锁定、没有延迟。
配合上面的弱口令，等于对着字典任人跑。

## 3. 谁在真正使用系统（决定了改密码会影响谁）

近 30 天登录记录：

| 账号 | 登录次数 | 最近一次 |
|---|---:|---|
| `operator@veggie.com` | 189 | 2026-08-08 |
| `boss@veggie.com` | 11 | 2026-08-08 |
| `driver@veggie.com` | 8 | 2026-08-07 |
| `restaurant1@veggie.com` | 4 | 2026-07-31 |
| `finance@veggie.com` | 3 | 2026-08-08 |
| `warehouse@veggie.com` | 2 | 2026-08-05 |

**42 个真实员工账号近 30 天一次都没登录过**（20 个 OPERATOR 里只有 3 个历史上登录过，
23 个司机 0 次）。

> 结论：**现在实际在跑生产的就是那几个种子账号**，真实员工账号基本是空壳。
> 所以「禁用种子账号」不是安全动作，是**直接把当前唯一在用的入口掐掉**。
