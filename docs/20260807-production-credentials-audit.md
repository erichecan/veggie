## 2. ⛔ 查出来的真问题：全部 51 个账号都是弱口令，且明文在 git 里

| 类别 | 账号数 | 密码 | 出处 |
|---|---:|---|---|
| 真实员工（gmail / hotmail / veggie.local 等） | 42 | `test123` | `scripts/import-users.ts:51`、`scripts/import-drivers.ts:44` |
| 种子演示账号（`*@veggie.com`） | 9 | `Demo1234!` | `prisma/seed.ts:27` |

**实测确认（生产站，只做登录、无任何写操作）**：

```
boss@veggie.com      / Demo1234!  → ✅ 登录成功，role=BOSS
operator@veggie.com  / Demo1234!  → ✅ 登录成功，role=OPERATOR
finance@veggie.com   / Demo1234!  → ✅ 登录成功，role=FINANCE
driver.moazzam@veggie.local / test123 → ✅ 登录成功，role=DRIVER
```

42 个真实账号只有 **6 个不同的 bcrypt 哈希** —— bcrypt 每次加盐结果都不同，
出现重复只能是导入脚本算一次哈希、复制给一整批人。

### 2.1 登录页曾把管理员入口直接摆在外面

`/enter` 上原有「一键登录」6 个按钮，密码 `Demo1234!` 写死在前端代码里，
点一下就以 BOSS 身份进入系统。**已于 20260807 移除**（本次提交），
只保留邮箱 + 密码表单。

⚠️ **移除按钮不等于账号安全了** —— 账号还在，密码还是那个，知道邮箱的人照样进得来。

### 2.2 登录接口的限流：有，但只按 IP

> ⚠️ **本节的第一版结论是错的，已更正。** 原写「没有任何速率限制」，依据是
> 「连打 8 次错密码全是 401」—— 而限额恰好是 **10 次/分钟**，8 次根本没到线。
> 用不足以触发的样本量去证明「机制不存在」，是个典型的假阴性。
>
> 同一轮还错了第二处：grep `/etc/nginx/sites-enabled/` 没找到 `X-Forwarded-For`，
> 就以为 Nginx 没透传真实 IP。实际 `sites-enabled/veggie` 是符号链接，
> `grep -r` 默认不跟随。真实 IP 一直是透传的。

重测（16 次连打）：第 1–10 次 401，**第 11 次起 429** —— `lib/rate-limit.ts` 生效。
Nginx 也确实设了 `X-Forwarded-For` / `X-Real-IP`（`/etc/nginx/sites-available/veggie`），
所以是按真实客户端 IP 分桶，不是全站共用一个桶。

**仍然缺的是**：
- **按账号限流** —— 换 IP 就能继续打同一个账号，10 次/分钟的约束对分布式来源无效
- **连续失败锁定** —— 失败再多也只是等一分钟，没有递增延迟、没有临时封禁
- 限流状态在**进程内存**里，多实例部署会各算各的（当前 droplet 单实例，暂不影响）

## 5. 任务台账

> 顺序是**故意**的：先加防护、再上强制改密流程、**最后才换种子账号密码**。
> 换密码的那一刻，当前在用的人就进不来了，必须等新密码交付到位才能做。

- [ ] **S1 登录防爆破补齐：按账号限流 + 连续失败锁定**
      现有的按 IP 10 次/分钟保留。新增：同一个邮箱连续失败达阈值后临时锁定，
      与来源 IP 无关（换 IP 绕不过）。锁定要**只影响该账号**，不能误伤别人。
      **验收**：同一账号换不同 IP 连续失败仍被锁；锁定期内即使密码正确也拒绝；
      锁定不影响其它账号登录；锁定到期自动解除；成功登录清零计数。
      **产出**：`lib/login-throttle.ts`、`app/api/auth/login/route.ts`、测试
      **依赖**：无

- [ ] **S2 首次登录强制改密**
      `User.mustChangePassword` 标记位；登录成功后若为 true，前端跳改密页；
      后端在 `withAuth` 里拦住除改密接口外的一切写操作，避免只靠前端跳转被绕过。
      给 42 个真实员工账号置 true。
      **验收**：带标记的账号登录后进不了任何业务页，只能改密；改完标记清除、能正常用；
      新密码不能与旧密码相同、不能是 `test123`/`Demo1234!` 这类已泄露口令；
      未带标记的账号完全不受影响。
      **产出**：`prisma/schema.prisma` + 迁移、`lib/auth.ts`、
      `app/api/auth/change-password/route.ts`、改密页面、测试
      **依赖**：S1

- [ ] **S3 种子账号换强密码（⛔ 最后做，且要先把密码交出去）**
      9 个 `*@veggie.com` 各生成一个随机强密码。**密码不进 git**，
      单独输出给用户。执行后当前会话全部失效，使用者需用新密码重新登录。
      **验收**：旧密码 `Demo1234!` 全部登录失败；新密码全部登录成功；
      `prisma/seed.ts` 里的硬编码密码同步改掉（否则下次跑 seed 又倒回去）。
      **产出**：一次性脚本 + `prisma/seed.ts`
      **依赖**：S2 完成并部署
