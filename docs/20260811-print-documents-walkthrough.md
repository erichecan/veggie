## 修复的两个问题

### P0 · 三类配送单据全部打成空白（种子数据缺陷）

现象：汇总单/配送单/签收单都显示「无订单 No orders」，客户数 0、订单数 0。

根因是**种子写的 `Trip.restaurants` 字段名与应用主路径不一致**：

| | 应用 `lib/trip-from-wave.ts` | 种子 `seed-events/events/sales.ts` |
|---|---|---|
| 客户 id | `restaurantId` | `customerId` |
| 客户名 | `restaurantName` | `customerName` |
| 订单 | **`orderIds: string[]`** | **`orderId: string`（单数）** |
| 波次 | 设 `waveId` | **不设** |

而 `lib/print/trip-loader.ts:102` 读的是 `r.orderIds ?? []` → 取到空数组 → 打印全空。

修法：种子按应用主路径的形状写（含按客户分组合并多单），并补上 `waveId`。
修复后 125/125 个行程都挂上了波次，打印数据接口返回 2 客户 / 2 订单 / 首单 6 行。

⚠️ 这是**测试数据缺陷不是应用缺陷** —— 真实行程都由 `trip-from-wave.ts` 生成，
形状本来就是对的。但它会让任何基于种子数据的打印验证得出「功能坏了」的错误结论。

### P1 · 发票行级 VAT 显示 14%，汇总显示 13.50%

同一张发票上两个税率。根因：行级用 `taxRate.toFixed(0)` 整数化，
而爱尔兰的 13.5% 和 4.8% 都带小数，整数化必错。

修法：新增 `formatVatRate()`，整数税率（23%）不显示多余小数位，带小数的保留。
配 3 个单测，其中一个专门断言**行级与汇总对同一税率必须指向同一个值**。

## 记录未改

- **打印页加载失败时永远停在 “Loading invoice…”**，不显示错误态。
  订单不存在时控制台有 404，界面却一直转圈 —— 打单员会以为是网络慢。
- **为打印一张单拉取全部客户**：`/api/customers` 返回 **1MB / 1331 条**，
  而打印只需要其中一个。与 A1 报告 P4 同源（全量拉取无分页）。
- **发票 Total 与 Subtotal+VAT 差 1 分**：€1063.49 vs €1063.50。
  行级 incl-VAT 各自四舍五入后累加，与「税前合计 + 税额合计」两条路径结果不同。
  金额不大但出现在同一张单据上，客户可能质疑。

## 自动化经验

打印页模板内嵌 `<script>window.print()</script>`，会弹出打印对话框**阻塞 JS 执行**——
Playwright 的 `browser_evaluate` 与 `browser_take_screenshot` 都会因此挂住/超时。
走查打印页要用 `browser_snapshot`（读无障碍树，不执行页面 JS）。
