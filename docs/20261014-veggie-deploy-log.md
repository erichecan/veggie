### 根因：客户截图 Pepper Green「走完销售流程库存回到原值」

- Place Order 页「确认」直接 `POST /api/orders` 建成 CONFIRMED。
- 扣库存只写在 `PUT` 的 PENDING→CONFIRMED 分支里，所以这条路径 **On Hand 从来没扣**。
- 中途下降的是 Forecast：旧算法对 WAVE_ASSIGNED / IN_DELIVERY 订单再减一次未送量；COMPLETED 后不再减，于是"涨回去"。
- 同一个"重复扣减"还出现在两处：
  - 波次缺货预警：库存 100，确认 60 后在手 40，却报「缺 20」；
  - 两套采购建议：已确认需求被减两次，导致建议偏大。

### 改动

- `StockLocation` 库位表：WH/Stock、供应商、客户、盘点调整、报废、期初。
- `StockMove` 新增：
  - from / to 库位；
  - 订单行、采购行；
  - 业务单位数量；
  - 单位成本、金额；
  - 客户/供应商、经手人。
- `qty` 仍是对在手量的带符号净影响，旧报表不受影响。
- 唯一入账函数 `lib/stock-ledger.ts`：11 个写库存的地方 + 商品导入全部改走它。扫描测试禁止别处再写在手量、批次余量或流水。
- 订单库存统一由 `lib/order-stock.ts` 按「目标 − 流水已拿」对账，覆盖：
  - POST 确认、PUT 确认 / 改行 / 撤回 / 取消；
  - 批量确认 / 取消；
  - 追加行、缺货改量、差异处理。
- 从没扣过库存的单在取消或减量时，不会再凭空多出库存。
- 存货估值凭证（永续盘存）：

  | 业务 | 借 | 贷 |
  |---|---|---|
  | 收货 | 1300 | 2150 |
  | 销售出库 | 5100 | 1300 |
  | 报废 / 盘亏 | 5200 | 1300 |
  | 客户退回 | 1300 | 5100 |
  | 退供应商 | 2150 | 1300 |

  供应商账单过账时冲平 2150，差价进 5000。
- Forecast 重写：

  | 字段 | 含义 |
  |---|---|
  | 在手 | Σ 流水 |
  | 占用 | 未送达订单在流水里实际拿走的量 |
  | 实物 | 在手 + 占用 |
  | 在途 | 已确认采购未收量，换算成基础单位 |
  | 预测 | 在手 + 在途 − 未扣库存的需求 |

- 界面：
  - 采购单「收货」弹窗新增「库存流水」；
  - 库存管理新增「库存流水」tab；
  - 销售订单新增「库存流水」按钮。
- 账本核对新增检查项：在手 = Σ流水、批次 = Σ批次流水、流水库位与方向、各库位合计为 0、已确认未占库存的订单、采购行已收 = Σ收退货流水、总账存货 vs 在手估值。

### 迁移 `20261014000002_stock_locations_double_entry`

1. 建库位表。
2. 历史流水按 type / sourceType / qty 符号回填 from / to（只写新列）。
3. 期初流水：批次余量、在手量与流水的差额各补一笔期初流水对平。在手量与批次余量一个都不改。
4. 存货期初凭证：Dr 1300 / Cr 3000，金额 = Σ 实物商品正库存 × 平均成本。

本地用构造数据跑过：

- 迁移后每个商品「在手 = Σ流水」，每个批次「余量 = Σ批次流水」，无缺库位流水；
- 期初凭证金额正确；
- 负库存和非实物商品不计入估值。

- 每张单单独一个事务，跑一次 `syncOrderStock`，逻辑与确认订单相同：单位换算、FEFO 扣批次、出库凭证 Dr 5100 / Cr 1300。
