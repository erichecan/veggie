### W1-1 司机端手写电子签名（完成）
合同第二条点名 Sign on Glass，第四条把「司机电子签收」写进验收闭环，审计实测全库零命中。

- `components/driver/SignaturePad.tsx`：纯 Canvas + Pointer Events，不引第三方签名库
  （几十行的事，引库多一份供应链与 CSP 风险）。一套 Pointer 代码同吃触屏/手写笔/鼠标；
  按 devicePixelRatio 放大再缩回，否则高分屏上签名是糊的；支持撤销一笔与清空重签。
- 司机端「✓ 完成此站」改为「✍️ 客户签收」——**签名成为送达的唯一入口**，
  必须有签名 + 签收人姓名才能确认。已签站点在页面上展示签名图与签收人、签收时间。
- `TripRestaurant` 加 `signature / signerName / signedAt` 三个字段，
  与退货照片、POD 同样以 base64 存在 `Trip.restaurants` JSON 里，不新增对象存储依赖。

**服务端完整性**（`lib/trip-signature.ts`）：签名是收货凭证，两件事不能让客户端说了算。
`PUT /api/trips/[id]` 是整包覆盖 restaurants JSON 的，不拦的话任何一次后续保存都能改掉凭证。
- 时间戳一律服务端打，客户端传的丢弃
- 已签名不可改、不可抹（409），要更正只能走主管纠错路径
- 只收 PNG data URI，解码后 ≤200KB（JSON 列塞不下几 MB 的图）
- 签收人姓名必填、trim、截断 40 字

**验证**：12 个单测 + 端到端实测。实测结果：
提交签名时客户端传 1999 年时间戳 → 落库为服务端时间 ✅；姓名两侧空白被 trim ✅；
篡改已有签名 → 409 ✅；抹掉签名 → 409 ✅；注入 `data:text/html` → 400 ✅。探针行程已清理。

### W1-2 客户签收单打印（完成）——M05-01 partial → **done**
合同第四条把「客户签收单」列进打印中心必须支持的单据，审计实测这是 6 类里唯一缺的。

- `lib/print/trip-receipt-template.ts`：一站一页。与送货单的区别是**送货单是送货前给客户看货与价的，
  签收单是送货后的凭证**——重点在谁签的、什么时候签的、签名长什么样。
- 已签收的印手写签名图 + 签收人 + 签收时间；**未签收的印空白签名栏**供纸质补签
  （现场断网或客户坚持要纸质回单时仍可用），而不是把这一站从单子上漏掉。
- 打印数据链路补 `TripSignoff`：`Trip.restaurants` JSON → loader → wire → 模板。
  老行程没有 signoffs 时按订单客户兜底，保证这张单永远打得出来。
- 入口：运营端行程列表加「✍️ 签收单」按钮；新增 `doc-badge` 的 `receipt` 类型（紫色）。

**验证**（分两半，因为 `trip-loader` 有 `import 'server-only'`，出不了 Next 运行时）：
- 模板：8 个单测（含 HTML 转义、空数据兜底、一站一页）
- 链路：HTTP 探针打 `/api/trips/[id]/print-data`，确认签名/签收人/签收时间/实收货款
  全部从库里流到接口，订单明细 10 条、客户资料 1 条。探针行程已清理。
- 审计探针重跑：**M05-01 partial → done**，6 类单据全 ✓
