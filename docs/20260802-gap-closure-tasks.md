      | 步骤 | 结果 |
      |---|---|
      | DNS | apex 与 www 都解析到 167.99.86.19（客户已配好） |
      | 证书 | Let's Encrypt，覆盖 `johnstonebros.ie` + `www`，2026-11-05 到期 |
      | 跳转 | `http://www` / `http://167.99.86.19` / `https://裸域` 三个入口全 301 到 www |
      | 协议 | TLS 1.3 ✓ TLS 1.2 ✓ TLS 1.1 拒绝 ✓ HTTP/2 ✓ |
      | 自动续期 | `certbot renew --dry-run` 通过（证明 ACME 路径没被 301 吃掉） |
      | 混合内容 | 0 处 |
      | 停机 | 0（nginx 热重载） |

      **上线顺序是有讲究的**：先把 HSTS 从两年降到 300 秒并部署（`14ba898`），
      再开 443。反过来的话，第一个 HTTPS 响应就把两年锁死在每个访问者浏览器里，
      证书一出问题就是打不开也点不掉。

      **落地时补的三个坑**（都不补的话故障会在 90 天后才显形）：
      1. `/.well-known/acme-challenge` 显式排在 301 之前 —— 否则首签成功、续期静默失败
      2. **续期后重载 nginx 的 deploy hook**：certbot 装完默认**没有**这个钩子
         （`certonly` 路径不带），续期会「成功」但 nginx 还在内存里发旧证书
      3. `options-ssl-nginx.conf` / `ssl-dhparams.pem` 在本机不存在（那是 nginx 插件包带的），
         TLS 参数改为自写片段 `snippets/veggie-tls.conf`，两个 server 块共用

      **配置已回写仓库**（`deploy/droplet/`），并与服务器上的逐字比对一致 ——
      否则下次 bootstrap 会把 TLS 配置盖掉。bootstrap 也补了「证书还没签时先用
      HTTP-only 配置」的分支：新机器上配置引用不存在的证书会让 nginx 直接起不来，
      而 certbot 又需要一个活着的 nginx 才能走 HTTP-01。

      ⚠️ **两件还没做完的**：
      - HSTS 仍是 300 秒。观察证书与续期几天后，要显式提交升回 `max-age=63072000`
        （不加 preload）。**这条不做，HTTPS 就是"可以被降级绕过"的**。
      - 任何用 `http://` + Bearer token 调接口的脚本/集成会失效：
        fetch 跨 http→https 重定向时**会丢掉 Authorization 头**，表现是 401。
        必须改成 https。（这是实测撞到的，不是推测。）

### W1-1 司机端手写电子签名（完成）
合同第二条点名 Sign on Glass，第四条把「司机电子签收」写进验收闭环，审计实测全库零命中。

- `components/driver/SignaturePad.tsx`：纯 Canvas + Pointer Events，不引第三方签名库
  （几十行的事，引库多一份供应链与 CSP 风险）。一套 Pointer 代码同吃触屏/手写笔/鼠标；
  按 devicePixelRatio 放大再缩回，否则高分屏上签名是糊的；支持撤销一笔与清空重签。
- 司机端「✓ 完成此站」改为「✍️ 客户签收」——**签名成为送达的唯一入口**，
  必须有签名 + 签收人姓名才能确认。已签站点在页面上展示签名图与签收人、签收时间。
- `TripRestaurant` 加 `signature / signerName / signedAt` 三个字段，
  与退货照片、POD 同样以 base64 存在 `Trip.restaurants` JSON 里，不新增对象存储依赖。

**服务端完整性**（`lib/trip-signature.ts`）：签名是收货凭证，两件事不能让客户端说了算。
`PUT /api/trips/[id]` 是整包覆盖 restaurants JSON 的，不拦的话任何一次后续保存都能改掉凭证。
- 时间戳一律服务端打，客户端传的丢弃
- 已签名不可改、不可抹（409），要更正只能走主管纠错路径
- 只收 PNG data URI，解码后 ≤200KB（JSON 列塞不下几 MB 的图）
- 签收人姓名必填、trim、截断 40 字

**验证**：12 个单测 + 端到端实测。实测结果：
提交签名时客户端传 1999 年时间戳 → 落库为服务端时间 ✅；姓名两侧空白被 trim ✅；

### W1-3 交账确认生成收款记录（完成）
审计缺口：财务确认交账**只翻转 `Trip.settlementStatus`，不生成任何 Payment**——
生产库 Invoice 148,285 张、Payment **0 条**，钱收了账上看不出来，对账仍靠人工比纸。

`lib/trip-settlement-payment.ts` 把「确认交账」变成真正的入账动作。三条设计取舍：

1. **不自动过账发票**。行程完成自动建的是 DRAFT 发票，而过账是财务动作，
   不该是交账确认的副作用。遇到 DRAFT 的**如实报告**（`unallocated` 里写明是哪张单），
   让财务自己决定要不要先过账——而不是替他们把账做了。
2. **按到期日从早到晚核销**（标准 AR 应用顺序），不是平均分摊。
3. **超收不硬塞**。实收超过未结清总额时，超出部分单列出来交人工判断（预付款还是录错），
   不静默吞掉也不硬记进发票。
4. **幂等**。靠 `Payment.note` 里的 `TRIP:<tripId>` 标记去重，网络重试不会重复记两笔钱。

**验证**：12 个单测（含跨票按到期日排序、草稿不过账、超收、多站不串账、
一票合并多单不重复计入、浮点毛刺）+ 端到端实测：
财务确认 → 生成 1 条 cash Payment 120 元 → 发票 paid=120/due=0/status=PAID → 
重复确认返回 `skippedAsDuplicate=true` 且 Payment 数不变。探针数据已清理。
