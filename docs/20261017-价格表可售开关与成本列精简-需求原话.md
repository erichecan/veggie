# 需求原话：价格表可售开关 + 成本列精简

日期：2026-10-17

## 来源

用户（eric）通过微信转发客户在价格表详情页截图（"M7M1N3干货-2"）上手写批注，截图上有 3 处红框标注。以下为截图批注文字逐字抄录（客户原话，非用户转述）。

## 客户原话（截图批注，逐字抄录）

针对 Variant Cost / Template Cost / Public Cost Price 三列：

> 这两个字段有需要吗？隐藏起来？

针对商品是否按这张价格表卖：

> 每个产品需要有一个可售/不可售的开关。不可售的话，这个产品不会出现在价格表的输出里，下单的时候也不会按这张价格表的价格来算。

针对为什么需要这个开关（业务背景说明，非独立功能点）：

> 因为季节性、运输等原因，产品会时有时没有，不是按库存判断能不能按这张表卖。

## 用户原话（对话中，指示跳过开发计划直接实现）

> "不用开发计划了,直接开始实现,实现完提交并部署"

## 实现落地对照

| 客户原话 | 落地方式 |
| --- | --- |
| "这两个字段有需要吗？隐藏起来？" | 经读代码核实：Variant Cost / Template Cost / Public Cost Price 三列渲染的是同一个 `cost` 变量（20260825 合表重构后 ProductTemplate 已删，三列本就是重复），删掉前两列只保留 Public Cost Price，印证了客户自己的判断 |
| "每个产品需要有一个可售/不可售的开关" | `OdooPricelistItem.selectable`（新增字段，`lib/types.ts`），价格表详情页表格新增「可售」列（内嵌勾选框）+ `ItemDialog` 弹窗同步加勾选框 |
| "不可售…不会出现在价格表的输出里" | `app/api/pricelists/print/route.ts`：打印/导出结果过滤掉 `selectable===false` 的规则行 |
| "下单的时候也不会按这张价格表的价格来算" | `lib/pricing-engine.ts` `matchesItem()`：`selectable===false` 的规则直接判不命中，下单定价自动回退到下一条匹配规则/最终牌价 |
